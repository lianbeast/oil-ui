# 工具

本目录自带的程序按下面的写法调用，不需要读源码；加 `--help` 打印同样的说明。

宿主有自己的浏览器工具时，查看页面、走查流程照常用。要交出下面这几样标准证据时，优先用这里的截图工具：它开一个独立的临时浏览器，不碰用户自己浏览器里的数据。本机缺 Node 22，或者没有 Chrome、Chromium、Edge 时，退回宿主工具，交出同样的几样东西。不为截图另写 Playwright 或浏览器协议脚本。

## 截图和录屏

### 什么时候截，截多少

截图分两种用途，不要混在一起：

- **看一眼**：改完一批，想看效果。只截当前这一屏，一条命令，不加 `--record`、`--motion`、`--mask` 和 `--sheet`。把一批改动攒在一起改完再截，不是每改一处截一次；页面没有变，就不重复截。
- **取证**：用 `--evidence` 一次取齐状态图、并排图、遮字图、首状态 200% 截图、首次出场录屏、动作录屏和 `--motion` 探测。只在两个时候做：送评审之前，交付之前。方向首屏那一轮每个方向只截一张，不取证。

每一轮评审只重新取这一轮改动影响到的证据。没有动过的状态和动效，沿用上一轮的文件，交接时注明哪些是沿用的；拿不准有没有被影响到，例如改了共享样式，就重取那一项。动效只在新做或改过以后重新录，`--motion` 也只在动效有变化以后重跑。

任务或项目已经指定了截图工具时，照用它，交出同样的证据即可：要的状态、200% 局部、动效录屏或三帧。下面的工具用来补它做不到的部分，例如动效探测。

```text
node <skill>/scripts/shoot.mjs <页面地址或 HTML 文件> [选项]
```

本地文件会用一个只监听本机的临时服务器打开。地址里带 `?` 或 `&` 时加引号，例如 `"http://127.0.0.1:3000/?state=done"`；也可以用 `--query "a=1&b=2"` 加查询参数，状态用 `--states`；两者可以一起用。不同调用的同名文件仍会覆盖。同一次调用里，重复状态、尺寸和倍数会去重并提示；不同结果遇到文件名冲突时，会自动加编号区分。

| 要什么 | 加上 |
| --- | --- |
| 送评审或交付前，一次取齐证据 | `--evidence --states idle,done --steps "send: click .send"` |
| 桌面单张 | `--size desktop`（1440x900） |
| 每个状态各一张，再拼成并排图 | `--states idle,running,done,error --sheet` |
| 同时要遮掉全部文字的版本 | 再加 `--mask` |
| 1 倍和 200% 各一套 | `--zoom 1,2` |
| 手机和桌面各一套 | `--size phone,desktop`（desktop 是 1440x900，phone/mobile 是 390x844；可混用数字尺寸，默认仍是 390x844） |
| 整页长图 | `--full` |
| 给用户指出问题：在元素上画框、标编号 | `--mark "1=.page-head .btn; 2=.toggle-row" --full`，另出一张 `<状态>-marked.png` |
| 截图前先操作几步 | `--steps "click .open; wait 300"` |
| 各从新页面开始，分别截图或录屏 | `--steps "open: click .open; wait 300" --steps "send: click .send"`，录屏再加 `--record` |
| 给地址加查询参数 | `--query "a=1&b=2"` |
| 先检查选项和动作写法，不开浏览器 | `--dry-run --steps "click text=More; wait450"`，标准输出是解析 JSON |
| 主操作录屏，外加开始、中间、结束三帧 | `--record --steps "drag .handle 0 -80; wait 400; click .start" --hold 1500` |
| 首次进入的出场录屏，从页面第一次有内容录起 | `--record --entry --hold 1500` |
| 动效探测：首次进入、主操作、从头滚到底各有没有动画、幅度多大 | `--motion --size 1440x900 --steps "click .primary"` |
| 截图还原：和参考图并排、叠加，出差异热图 | `--compare 参考.png --size <参考的逻辑尺寸>` |

`--mark` 里每组写成“编号=选择器”，用分号隔开，编号和消息里问题的编号一致；一组匹配到的元素都框上，编号标在第一个上；找不到元素会直接报错。整页的问题加 `--full`，否则首屏以下的框截不进来。

`--steps` 用分号隔开动作。引号、方括号、圆括号里的分号不拆。`click`、`hover`、`dblclick` 后面整段都是选择器，带空格也不用包引号，例如 `click .nav button:nth-child(3)`、`click [aria-label="Send money"]`。整段包了一对引号时也认。

- `drag 选择器 横向位移 纵向位移`：最后两个数是位移，例如 `drag .tiles .paper 240 0`。
- `type 选择器 文字`：选择器是第一个词，括号和引号里的空格不拆。后代选择器包引号，例如 `type ".form input" "hello world"`。文字两端的一对引号会去掉，文字插入当前光标处。
- `fill 选择器 文字`：写法同 type，先清空输入框、文本域或可编辑元素的原内容，再填入文字，并触发 input 和 change。例如 `fill #message "hello world"`。
- `select 选择器 值`：操作原生下拉框，按 value 或可见文字选，并触发 input 和 change。
- `waitfor 选择器`：最多等 5 秒，等元素出现并可见。
- `key 按键`：认 `Meta+A`、`Control+A`、`Shift+Tab`、`ControlOrMeta+A`；最后一种在 macOS 用 Meta，其他平台用 Control。
- `scroll 纵向位移`；`wait 450`、`wait450`、`wait 450ms`、`wait 0.5s` 都认。

别名：`doubleclick` 是 `dblclick`，`press` 是 `key`，`sleep` 是 `wait`。

选择器除了 CSS，还认 `text=More`、`text="Send money"` 和 `button:has-text("Undo")`。`text=` 先找可见文字相等的，再找包含的；取最深的元素，同样深时优先可点击的元素。`:has-text()` 在 CSS 匹配里取第一个可见、文字包含的元素，单双引号都认，省略前面的 CSS 时查全部元素。这些写法在动作和 `--mark` 里通用。点击和悬停只在元素位于视口外时滚动。匹配多个元素时，优先操作第一个可见的；都不可见时，报出匹配数量和隐藏原因，提示先让它出现或换用可见元素。错误里的示例优先用实际线索，文字线索先按包含关系、再按相似度排序。

点击、双击和悬停前检查中心点。被其他元素挡住时提示遮挡元素的选择器；有 disabled、aria-disabled="true" 或 pointer-events: none 时提示禁用原因。提示写进输出和 report.json 的 issues，计入最后的问题汇总；动作照常执行，返回码不变。

选择器只在主文档里找，不进入 iframe 或 Shadow DOM。找不到元素时，页面若有 iframe 或开放的 shadow root，错误里会列出数量。

`--steps` 可以写多次。组名写在开头，格式是字母数字、下划线或连字符，加冒号和空格，例如 `open: click .open`；动作名不能当组名。每组都从重新打开的页面开始。没有名字的多组按 1、2、3 编号。选项可以写成 `--名字=值` 或 `--名字 值`，`--motion`、`--record` 等开关不带参数。

`--evidence` 依次截每个状态的 1 倍图，两个以上状态时再出并排图和遮字并排图；再截第一个状态的 2 倍图、探测动效、录首次进入的出场、录每组动作。首次出场用 `record-entry.mp4` 和 `motion-entry-start/mid/end.jpg`，动作组名为 entry 时出场改用 entry-appearance；名字仍冲突时继续加 -appearance。所有结果进同一个目录和 report.json。一项执行失败会写进汇总，继续其他项，返回码为 1。每组录屏结束或失败后都会清理临时帧目录，已生成的截图和三帧保留。

结果写进 `--out` 指定的目录，默认是 `./shots`：每个状态一张 `<状态>.png`，遮字版是 `<状态>-masked.png`，标注版是 `<状态>-marked.png`，并排图是 `sheet.png` 和 `sheet-masked.png`，单个无名动作组的录屏仍是 `record.mp4` 和 `motion-start/mid/end.jpg`；具名或多组用 `record-<组名>.mp4` 和 `motion-<组名>-start/mid/end.jpg`，截图也带组名。多个倍数各出一套，2 倍文件名加 `-@2x`。每张图都会检查控制台错误、横向溢出和没加载出来的图片，命令最后一行给出结论，明细在 `report.json`。录屏需要本机装了 ffmpeg，没有时只留三帧。

截图在 `--wait` 之后再等有限时长的动画和过渡结束，每张截图额外最多等 2 秒，不等无限循环；有动作时，操作前后共用这 2 秒。实际等待毫秒数写进 `report.json` 的 `animationWaitMs`。录屏和动效探测保持原来的时机。

单个 CDP 请求最多等 30 秒。超时或浏览器意外断开时，报出当前步骤或操作，清理临时目录后退出，返回码为 1。

每张截图还会查一组能从页面样式里直接判断的问题，命令输出里以“默认做法提示”列出，明细在 `report.json` 的 `lint` 字段：

- **要改的可读性问题**：文字对比度不达标（正文低于 4.5:1，大字低于 3:1）、正文小于 13px、多行正文行高过紧、首屏里停在透明状态的内容（出场动画没触发）。
- **改掉或写出理由**：有色底上的灰字、正文行太长，以及模型默认做法：标题上方的眉标和编号标签、彩色单侧边线、渐变文字、卡片里套卡片、表情符号当图标、中文界面里的英文大写标签、标题离上文比离下文还近。保留的项，在交付说明里写出它怎样服务方向。

检查会误报，例如真实的步骤编号、确实需要的标签；误报也在交付说明里写一句。对比度低于 1.5:1 的文字通常是背景没查准，工具不报，这类地方自己看截图。它只认得写法，判断不了好不好看：提示清零之后，仍要自己看截图。

`--compare` 用在截图还原上：参考图按宽度缩放到截图的宽度，每张截图另出一张 `<状态>-compare.png`，四格依次是参考、当前、叠加和差异热图；热图把亮度差异明显的像素标红，并按九宫格标出各格的差异像素占比，命令输出写整体占比和最多的三格。先用 `--size` 设成参考图的逻辑尺寸，例如参考是 2880 宽的 2 倍图，就用 1440 宽，否则比的是两张错位的图。文字和图片内容不同也会抬高差异，所以这个数只用来找先修哪一块、看修改有没有让差异变少，不当作还原度的分数。

`--motion` 只是底线检查，结果写在 `report.json` 的 `motion` 字段：首次进入没有动画、只有持续循环没有出场、`--steps` 动作没有反馈、幅度小到看不出来，都会记为问题；落地页类页面从头滚到底没有任何变化，也记为问题。另外会报告首屏滚动 1.5 屏内有几层在变、幅度多大，只作参考，不记为问题；页面选了首屏景深时用它核对。它只说明“动了没有、动了多少”，好不好看仍要看录屏、交评审。新界面和落地页送审前先跑一次，报问题就先补动效。页面本身不能滚动时（单屏 App、小游戏），工具会跳过滚动检查；能滚动的 App 页面报了这一项，在交付说明里写一句不适用即可。Canvas 和 WebGL 里的动画可能探测不到，这时以录屏为准。`--motion` 和 `--record` 可以一起跑，录屏会重新打开页面。

WebGL 页面在没有显卡的机器上会改用软件渲染。画布没能创建绘图上下文、或者上下文丢失时，检查会记为问题：这时截图照样成功，画面却是空的，不能当证据。

检查报出接口 401、404 这类和画面无关的错误时（例如访客状态下的登录接口），在交付说明里记一行就行，不为了让检查通过去改登录、接口这类业务代码。

交给评审前先自己看一眼结果：默认状态是不是已经加载完，遮字版有没有把图形也一起盖掉。证据有错先重截，再交给评审。

## 写可操作的小样

小样要能用地址参数直接打开每个状态，例如 `?state=done`，截图工具和评审都靠它。一个组件或一个页面只写一个文件，不要每个状态复制一份。

颜色、字号、间距、圆角先定成十来个 CSS 变量，后面一律引用变量；同一个组件的样式用原生 CSS 嵌套写在一起。不引入 Tailwind 或 Sass 这类需要构建的工具。

表单、切换、展开这类状态和交互，用 Alpine.js 写在 HTML 属性上，不手写一长段切换显示的脚本。手势跟手、物理模拟、Canvas 和 WebGL 绘制、音频放进单独的 JS 模块，每帧更新的数据不放进 Alpine 的响应式状态；Alpine 只读模块给出的结果来更新文字和按钮。组件方法里要找别的区域时用 `$refs`，不用 `$el`：`$el` 指向触发事件的那个元素。

接入 Alpine.js：

1. 复制到任务目录：`cp <skill>/assets/vendor/alpine.min.js <任务目录>/vendor/`
2. 页面里引用：`<script defer src="vendor/alpine.min.js"></script>`
3. 状态集中放在一个 `x-data` 里，初始状态读地址参数：

```html
<main x-data="{ state: new URLSearchParams(location.search).get('state') || 'idle', amount: 40 }">
  <p x-show="state === 'done'">做好了</p>
  <input type="range" min="20" max="80" x-model.number="amount">
  <button @click="state = 'running'">开始</button>
</main>
```

放进对比页时，在 manifest 里给这个候选加 `"interactive": true`。生成器会把任务目录里引用到的 CSS 和 JS 文件内联进对比页，不用手动合并。

存量项目里照用项目自己的技术栈，不引入 Alpine.js。
